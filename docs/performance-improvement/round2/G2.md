## M2/M3: `--cells 64:4096`, 5 rounds (`g2-64k`)

| variant | proxy % | json p99 | proxy p99 | payload MB/CPU-s | vs monoio |
|---|---|---|---|---|---|
| tokio | 95.0 | 8.97 ms | 21.6 ms | 1,102 | |

| `budget16` | **27.8–28.4** | 8.97 ms | 17.9 s | 1,554 | proxy collapses |

| `budget61:lifo` | 95.0 | 9.30 ms | 40.6 ms | 1,581 | payload −2.8% (tie), json −33.5%* |
| `acceptbatch` | 95.0 | 15.2 ms | 41.0 ms | 1,583 | ties |
| `acceptbatch:opendirect` | 95.0 | 15.7 ms | 39.5 ms | 1,562 | ties (files are cached; no punt to save) |
| `acceptbatch:budget16:lifo` | 95.0 | 9.60 ms | 36.7 ms | 1,495 | payload −8.1%* |
| `acceptbatch:budget61:lifo` | 95.0 | 9.27 ms | 40.2 ms | 1,571 | json −33.8%* |

(* counts by the 8% rule.)

**Reading.**
- The LIFO slot fixes M2's mechanism exactly as G0 predicted. A fixed budget without it starves waker hand-overs (proxy
  at 28–36% of target). With it, the fixed budget keeps json's gain: json p99 ≈ tokio's (+3.7%).
- **Decision:** `lifo_slot` stays opt-in (it costs 2–3% payload with no gain under the default budget), and the docs
  pair it with `task_budget(n)`: AGENTS.md already says "combine it with `lifo_slot(true)`". `budget61:lifo` is the
  recommended setting for latency-sensitive mixes.
- **M3 remains:** proxy p99 is ~40 ms under every setting (tokio 21.6). The budget shortens the wait of a CQE-driven
  wake and fixes json, but proxy doesn't move, so its tail comes from something other than queue traversal. A proxy
  request is client read → upstream lease → upstream write/read → client write: several CQE wakes, plus the upstream
  pool. Candidates for W2-retry: the upstream pool's wait queue (FIFO vs the lease hand-over), the CQE-wake path
  (each CQE wake goes to the back of the queue, so a request with k IO steps waits k traversals), and the reproducer's
  `--hop --pool` mode with a metrics build to get per-step waits.

**F1 passes:** the coop budget doesn't throttle the batch accept (it's a `MultishotOp`, not budgeted), M1 holds,
and repl p99 on the encrypted mix stays within 8% (+1.0%). It is also neutral: in the benchmark's server, op
futures are `Pending` on their first poll, so a task rarely drains more than a few ready results per poll and the
budget almost never fires (G0/W1-sched: `coop_yields` = 0 for streams). `yield_now` and `consume_budget` are the
tools for CPU-bound loops, which this benchmark does not have.
