## M5: `--cells 1024:2000 --workloads repl --repl-conns 2000` (4 KiB at 150k/s, 16 KiB at 120k/s)

| variant | 4 KiB MB/CPU-s | fr/s | vs tokio | 16 KiB MB/CPU-s | fr/s | vs tokio |
|---|---|---|---|---|---|---|
| tokio | 450.7 | 105.5k | | 1,269 | 74.4k | |
| `acceptbatch` | 415.1 | 97.5k | −7.9% | 1,176 | 69.1k | −7.4% |
| `acceptbatch:fixedfd` | 415.7 | 97.5k | −7.8% | 1,176 | 69.1k | −7.4% |
| `acceptbatch:recvmulti` | 398.4 | 93.5k | −11.6%* | 991 | 58.3k | −21.9%* |
| `acceptbatch:budget61:lifo:smallio16` | 426.3 | 100.1k | −5.4% | 1,171 | 68.9k | −7.8% |

(* counts by the 8% rule.)

- The analyzer marks several 16 KiB rows "timeout". That is its `lat_max ≥ 10 s` rule, not failed requests: this cell
  is offered above capacity, so the max latency is queueing time (tokio 9.1–9.8 s, monoio 10.6–11.8 s). There are
  0 client errors and 0 timeouts in every row of both cells.
- Against W2-lead (wave-1 tree: −8.0% / −9.3%), the W2-m5 work moves 16 KiB from failing to −7.4%. 4 KiB is unchanged
  within noise. W2-lead's profile still holds: the remaining gap is the kernel's per-request cost of io_uring
  recv/send against tokio's `recvfrom`/`sendto`, not the runtime.
- `fixedfd` is a tie (+0.1%): the `fput` share (~1%) is below resolution.
- `recvmulti` (incremental 1024 × 64 KiB ring) no longer stalls (W2-recvinc fix: stable in all 10 rounds), but costs
  more on this cell (+66 MiB RSS for the ring, one copy per byte into the SUT's frame buffer). Not a recommendation for
  small-frame servers; it remains the tool for many idle connections.

## M3: `--cells 64:4096` (`g3-m3`)

| variant | json % / proxy % | json p99 | proxy p99 | stream p99 | payload MB/CPU-s |
|---|---|---|---|---|---|
| tokio | 95.0 / 95.0 | 8.42 ms | 20.6 ms | 69.0 ms | 1,089 |
| monoio | 95.0 / 95.0 | 13.0 ms | 41.3 ms | 23.8 ms | 1,554 |
| `budget61:lifo` | 95.0 / 95.0 | 9.47 ms | 41.6 ms | 24.4 ms | 1,551 |
| `budget61:lifo:smallio16` | 95.0 / 95.0 | **6.15 ms** | **13.5 ms** | 24.9 ms | 1,546 (−0.5%) |
| `acceptbatch:budget61:lifo:smallio16` | 95.0 / 95.0 | 6.46 ms | 13.7 ms | 25.7 ms | 1,584 (+2.0%) |
| `budget16:lifo:smallio16` | 95.0 / 95.0 | 5.67 ms | 10.4 ms | 26.7 ms | 1,510 (−2.8%) |

`small_io_priority` fixes the mechanism found by W2-m3: a proxy request's ~4 CQE wakes no longer each wait a full
ready-queue traversal behind the stream tasks. Proxy p99 drops 67% vs monoio and is 35% below tokio; stream p99 rises
by ~1 ms (+4.6%, a tie) and payload stays +42% above tokio. `budget16` cuts tails further at −2.8% payload.
Recommended latency setting: `task_budget(61)`, `lifo_slot(true)`, `small_io_priority(Some(16 * 1024))`.
