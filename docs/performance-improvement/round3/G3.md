# Gate G3: the final tree against 0.8.0, and the one-configuration question

Tree: `r3-g2` (code identical to the 0.9.0 release). Builds without `metrics`.

## Regression check against 0.8.0 (same session, same machine, quiet)

`reqresp` from tag `r3-g0` (0.8.0 code plus the reproducer) against the final tree, default path (`pipe`: no new
API in use) with `--ring defer,skipenter,ringfd`, medians of 3 runs of 5 s:

| load | 0.8.0 frames/s | 0.9.0 frames/s | p99 | user instructions / frame | all cycles / frame |
|---|---|---|---|---|---|
| 8 connections, 4/16/64 KiB | 95,108 | 96,151 (+1.1%) | 170 → 166 µs | 2,084 → 1,554 | 45,069 → 44,579 |
| 2000 connections, 4 KiB | 110,944 | 112,912 (+1.8%) | 18.6 → 18.1 ms | 2,342 → 1,795 | 38,628 → 37,958 |
| 9 connections + 2 bulk writers (8 KiB work per chunk) | 57,644 | 58,044 (+0.7%), bulk 456 → 457 MB/s | 299 → 299 µs | 13,665 → 13,019 | 74,296 → 73,786 |
| `smallframes` 2000 × 4 KiB (with `timeout` per frame) | 115,768 | 120,892 (+4.4%) | — | 2,671 → 2,107 | 37,017 → 35,446 |

No loss anywhere (the 8% rule asks for none); the default path is 0.7–4.4% faster and uses 21–25% fewer
user instructions. On the bench the unchanged configurations of ROUND3.md's first table measured in this session
(G1) at R8 `FEW` 97,935 / `MANY` 99,037 (ROUND3.md: 97,745 / 98,525), R2000 `MANY` 114,254 (114,816), MIX `FEW`
54,189 (53,862): the same within noise, across sessions.

## One configuration for all three loads

Measured in G1 ("One configuration"): `defer:skipenter:pipeack:mshot:wset72:ringfd:fixedfd:acceptmulti:drain2:eagerack`
passes the bounds set for this gate: MIX within 3% of `FEW` (+1.8%, ack p99 204 µs against 225), R2000 ties
`MANY` (−0.7%), R8 ack p99 (113 µs) not above tokio's range (103–120). AGENTS.md recommends it ("Recommended
configuration for request/response servers"). Both problems of ROUND3.md are closed: one ring configuration,
and an ack p99 at 8 connections inside tokio's range instead of +27%.

What stays open is in [docs/TODO.md](../../TODO.md) (and the package notes' open questions): the "first 64
connections on per-connection buffers" split of the bench server has no crate helper; `drain_taskrun(2)` was
chosen from loopback measurements of 1, 2 and 4; `send_then_recv` loses on `defer` with many connections.
