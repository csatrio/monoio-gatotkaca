# Gate G2: wave 2 on the bench

Tree: `r3-wave2`. Bench: `../gatotkaca-transport` working tree with `pairack` added to the `--tune` items and the
facade backend (`gatotkaca-transport-monoio`) rebuilt on the `_op(&self)` methods; results in `results/r3-g2-*`.
Machine quiet, `performance` governor, 3 rounds of 10 s per cell. `FEW`/`D` as in G1.md (all with `acceptmulti`).

## C1: `send_then_recv` against `send_op` + `recv_poll_first_op` and against `send_eager`

| load | ring | pair | pipelined pair of ops | eager |
|---|---|---|---|---|
| R8 | `defer` (`D`) | 98,344 frames/s, ack p99 111 µs [108–111] | 98,325, 136 [136–137] | 97,947, 110 [109–110] |
| R8 | `coop` (`FEW`) | 97,609, 117 [116–118] | 97,303, 140 [140–141] | 95,138, 146 [144–147] |
| R2000 | `defer` | 103,743, 21.0 ms [20.0–23.7] | **109,221**, 19.2 [19.0–21.4] | 107,242, 19.6 [19.2–19.8] |
| R2000 | `coop` | 97,498, 21.3 [21.2–21.6] | 97,509, 21.2 [21.0–21.3] | 95,595, 21.7 [21.6–21.9] |

- Task polls per frame: 1.00 with the pair (reproducer, `metrics`), 2.00 with the pair of ops, 1.00 with eager;
  CQEs per frame 1 / 2 / 1; SQEs per frame 2 / 2 / 1. The ≤ 1.1 polls bound is met.
- **R8 passes on both rings**: frames/s tie the pair of ops (+0.0% / +0.3%), ack p99 falls from 136–140 to
  111–117 µs, the same as the eager ack on `defer` and better than it on `coop` (where the eager ack's syscall
  runs the ring's task work unbatched: 146 µs, −2.2% frames/s).
- **R2000 on `coop` passes**: a tie (−0.0%), with the eager path at −2.0%.
- **R2000 on `defer` fails the "not below the pair of ops" bound: −5.0%** (the eager path: −1.8%). The cause is
  in the kernel's design (G0, KV2): on a `DEFER_TASKRUN` ring the linked receive is started by a deferred
  task-work item, so a pair costs two items per frame against one, and a park that is capped at 20 items
  delivers 20 frames instead of 40 (`frames_per_round` 20.0 against 40.0 in the reproducer). `drain_taskrun(2)`
  recovers the round size but not the throughput (−3.6% in the reproducer).
- **Verdict: C1 passes for few connections on either ring and for many connections on `coop`; on `defer` with
  many connections `send_eager` + `recv_poll_first_op` stays the recommendation** (AGENTS.md says so). The
  single-configuration recommendation of G1 is unchanged.
- Also delivered: `submit_chain` accepts the skip shape (`SKIP_SUCCESS` on all but the last member: one slot,
  one CQE), which is what ROUND3.md's raw form asked for.

## A1: the facade backend on `recv_op` / `send_op` / `send_vectored_op`

`gatotkaca-transport-monoio` holds the `TcpStream`/`UnixStream` whole and uses the `&self` futures: no
`into_split`, no half moved through a `Cell` per operation, `send_vectored_op` instead of `writev` (so a reset
peer gives `EPIPE`, never `SIGPIPE`). Same binary otherwise, same session:

| `gk-monoio`, R8 | frames/s | ack p50 | ack p99 [min–max] |
|---|---|---|---|
| before (`into_split`, `writev`) | 91,618 | 70 µs | 149 [149–150] |
| after (`_op(&self)` methods) | 91,695 | 69 | 154 [149–154] |
| `gk-tokio` | 89,534 | 81 | 115 [109–117] |

- **A1 passes**: not below the current build (+0.1%); p99 within one round's spread. No allocation per write:
  the vectored send takes its `msghdr` from the per-thread pool or, on this 7.0 kernel, uses the vectorized
  plain `SEND` with no `msghdr` at all (the crate's `vectored_alloc` test counts zero allocations for 1000 sends
  in every form); the facade's `IoVecArray` is kept per connection. The facade's conformance tests pass.
- The facade does not use `send_eager` yet; its replies would gain the R8 p99 of the eager ack (G1) with one
  call. Bench-side follow-up.
- Reproducer, 3-iovec reply at 2000 connections (exact user instructions per frame): boxed `msghdr` 2,443 →
  pool 2,113 → vectorized `SEND` 2,100 (r3-vec.md).
